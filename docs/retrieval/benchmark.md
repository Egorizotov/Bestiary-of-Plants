# Benchmark поиска и RAG

**Статус:** план оценки и начальный набор запросов. Измеренные метрики появятся после реализации retrieval pipeline; значения ниже являются целями для обсуждения, а не уже достигнутыми результатами.

## 1. Зачем нужен benchmark

Benchmark позволяет проверить, находит ли BM25 нужные документы, не ухудшается ли поиск после изменений и насколько ответы LLM опираются на извлечённый контекст. Изменения следует оценивать на одном и том же наборе запросов.

## 2. Состав одного тестового случая

Каждая запись должна содержать:

- `query_id` — стабильный ID;
- `query` — запрос пользователя;
- `expected_doc_ids` — документы, которые эксперты считают релевантными;
- `intent` — тип вопроса;
- `should_abstain` — ожидается ли отказ от уверенного ответа из-за недостатка корпуса;
- `notes` — примечания для проверяющего.

Эталонные ID добавляются после того, как корпус реально создан. До этого в таблице ниже указаны ожидаемые названия документов/тем, а не готовые ID.

## 3. Начальный набор запросов

| ID | Запрос | Ожидаемые релевантные документы / тема | Тип |
|---|---|---|---|
| Q01 | Что такое венерина мухоловка? | Венерина мухоловка; Dionaea muscipula | Поиск вида |
| Q02 | Чем венерина мухоловка отличается от росянки? | Венерина мухоловка и росянка; тип ловушек | Сравнение |
| Q03 | Какие растения относятся к хищным? | Статьи о венериной мухоловке, росянке и непентесе, если они есть в корпусе | Категоризация |
| Q04 | Каково научное название венериной мухоловки? | Источник с подтверждённым научным названием Dionaea muscipula | Точный факт |

| Q07 | Почему росянку называют хищным растением? | Источник о росянках и механизме ловли | Объяснение |

| Q09 | Какие растения опасны для человека? | Только подтверждённые корпусом материалы о конкретных токсичных видах | Безопасность |
| Q10 | Можно ли есть незнакомое растение, если оно похоже на съедобное? | Источники о рисках ошибочной идентификации; ожидается безопасный ответ без разрешения на употребление | Безопасность / abstain |

| Q12 | Определи растение по этой фотографии | В текущем MVP нет визуального распознавания | Вне рамок |

| Q14 | Расскажи о раффлезии | Источник о Rafflesia и её особенностях | Поиск вида |

Список требует проверки после формирования фактического корпуса. Запросы Q08–Q11 должны быть особенно тщательно сформулированы, чтобы не оценивать систему по неоднозначному или медицинскому вопросу без подходящих источников.

## 4. Процедура оценки

1. Зафиксировать версию корпуса, параметры BM25 и дату прогона.
2. Для каждого запроса получить топ-5 документов.
3. Сравнить выдачу с `expected_doc_ids`, оценёнными вручную.
4. Отдельно проверить запросы, где правильное поведение — сообщить о недостатке данных.
5. Для RAG оценить фактические утверждения ответа, поддержку каждым утверждением источниками и корректность показанных ссылок.
6. Сохранять результаты, чтобы сравнивать версии.

## 5. Метрики

- **Recall@5:** доля известных релевантных документов, которые попали в первые пять результатов.
- **Precision@5:** доля релевантных документов среди первых пяти результатов.
- **nDCG@5:** метрика ранжирования с учётом позиции релевантных документов; использовать, если у команды есть шкала градаций релевантности.
- **Groundedness:** доля проверенных фактических утверждений ответа, которые действительно подтверждены найденным контекстом.
- **Citation correctness:** доля ссылок, которые ведут на реальные источники, использованные в ответе.
- **Abstention correctness:** корректность отказа от уверенного ответа, когда корпус не даёт достаточного подтверждения.

Начальная цель для обсуждения: Recall@5 не ниже 0,80 на ручном тестовом наборе и отсутствие ссылок, не соответствующих реальным документам. Это ориентиры для учебного проекта; их необходимо подтвердить на фактическом корпусе, а не указывать как достигнутый результат до замеров.

## 6. Формат результатов

Рекомендуемые колонки CSV/таблицы: `run_id`, `corpus_version`, `query_id`, `query`, `top5_doc_ids`, `relevant_doc_ids`, `recall_at_5`, `precision_at_5`, `answer`, `source_ids`, `groundedness_notes`, `abstention_correct`, `reviewer_notes`.

## 7. Требование к воспроизводимости

Любое изменение токенизации, нормализации, разбиения на фрагменты, параметров BM25 или промпта LLM должно сопровождаться повторным прогоном одного и того же benchmark. Нельзя сравнивать два результата, если одновременно изменились корпус и метод оценки без фиксации этих изменений.
