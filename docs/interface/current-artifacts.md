# Существующие интерфейсные артефакты

Документ фиксирует уже созданные материалы и связывает их с документацией продукта. Он не требует повторно разрабатывать HTML или макет Figma.

## 1. HTML-страница

- **Статус:** HTML-прототип уже существует.
- **Фактический путь:** проверить перед сдачей. В шаблоне README предполагается `frontend/index.html`; если файл находится в другом месте, указать здесь реальный путь.
- **Что проверить:** страница открывается; основные элементы соответствуют макету; ссылки на CSS/JS/изображения не сломаны; кнопки и поле ввода ведут себя так, как заявлено в демонстрации.
- **Связанные требования:** `../product/requirements.md`; спецификация поведения — `interface-spec.md`.

## 2. Макет Figma

- **Статус:** макет уже существует.
- **Ссылка:** добавить реальный URL Figma перед сдачей. Ссылка не могла быть заполнена автоматически, так как не была передана в чат.
- **Доступ:** проверить открытие ссылки в режиме просмотра для человека, не состоящего в команде, если это соответствует требованиям курса.
- **Что проверить:** макет показывает основной сценарий и основные состояния интерфейса; его названия и формулировки не противоречат продуктовой спецификации.

## 3. Сверка HTML и Figma

Перед контрольной точкой сопоставьте:

- заголовок и краткое описание продукта;
- место ввода запроса и действие отправки;
- способ отображения результата/карточки растения;
- способ показа источников (если они уже есть в дизайне);
- состояния загрузки, пустого ответа и ошибки — в макете или документации;
- адаптивность на узком экране, если она предусмотрена.

Не требуется добавлять backend только ради того, чтобы HTML выглядел работающим. Если данные статические, обозначьте их как демонстрационные.
