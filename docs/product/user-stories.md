# Пользовательские сценарии

## UC-01. Найти растение по названию

**Как** человек, изучающий растения, **я хочу** ввести название растения, **чтобы** быстро открыть краткое описание и перейти к источнику.

**Предусловие:** пользователь находится на главной странице; доступен поисковый интерфейс.  
**Основной поток:**
1. Пользователь вводит название, например «венерина мухоловка».
2. Отправляет запрос.
3. Система показывает соответствующие результаты.
4. Пользователь выбирает карточку и читает доступное описание.
5. При наличии источника пользователь может перейти к нему.

**Альтернативы:** если результатов нет, показывается пустое состояние с советом уточнить запрос; при технической ошибке показывается сообщение и возможность повторить запрос.

**Критерий приёмки:** пользователь может понять, найден ли нужный вид, а результат имеет понятное название и описание. Ссылки на отсутствующие источники не создаются.

## UC-02. Задать вопрос о свойствах растения

**Как** пользователь без специальных знаний, **я хочу** сформулировать вопрос обычным языком, **чтобы** получить понятное краткое объяснение.

**Пример запроса:** «Чем венерина мухоловка отличается от росянки?»

**Основной поток:**
1. Пользователь вводит вопрос.
2. Frontend передаёт вопрос backend.
3. Backend выполняет поиск релевантных фрагментов корпуса.
4. Если предусмотрена генерация, backend передаёт вопрос и найденный контекст модели.
5. Frontend отображает ответ и список использованных источников.

**Альтернативы:** при отсутствии подходящих материалов система не должна придумывать ответ; при ошибке поиска или LLM пользователь получает понятное уведомление.

**Критерий приёмки:** ответ отделён от источников визуально; пользователь может понять, на каких материалах он основан.

## UC-03. Получить ответ при недостатке данных

**Как** пользователь, **я хочу** видеть сообщение, когда корпус не содержит достаточной информации, **чтобы** не принять догадку за подтверждённый факт.

**Пример:** «Можно ли безопасно употреблять неизвестное растение?»

**Ожидаемое поведение:** интерфейс сообщает, что данных недостаточно для вывода и продукт не заменяет консультацию специалиста. Не выдаются инструкции по употреблению или самолечению.

## UC-04. Повторить запрос

**Как** пользователь, **я хочу** изменить формулировку после пустой выдачи или ответа, **чтобы** уточнить поиск без повторного открытия сайта.

**Критерий приёмки:** поле ввода остаётся доступным; новый запрос не смешивается с результатами предыдущего.

## Демонстрационный сценарий первой точки

Поскольку реальный поисковый backend может ещё отсутствовать, для демонстрации используется существующий HTML-прототип. Команда показывает основной путь на тех элементах, которые действительно реализованы, и отдельно называет заглушки. Не нужно выдавать статическую демо-карточку за результат реального RAG.
