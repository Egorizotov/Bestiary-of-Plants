# Рабочий процесс AI-агента

## Алгоритм выполнения задачи

### 1. Понять запрос

- Определи ожидаемый результат и критерии приёмки.
- Найди связанные требования, пользовательские сценарии и владельцев компонентов.
- Проверь, не противоречит ли задача существующим решениям.

### 2. Исследовать репозиторий

- Проверь `git status`; не перезаписывай чужие незакоммиченные изменения.
- Изучи затронутые файлы и соседние примеры.
- Определи стек по реальным конфигурационным файлам.
- Найди существующие команды запуска и проверки.

### 3. Планировать минимально достаточные изменения

- Перечисли файлы, которые нужно изменить.
- Если API, формат документов, контракты или продуктовый сценарий затрагиваются — сначала согласуй/обнови спецификацию.
- Не делай массовый рефакторинг вне задачи.

### 4. Выполнить

- Двигайся небольшими согласованными изменениями.
- Повторно используй текущие компоненты и зависимости.
- Помечай демонстрационные данные как mock/demo.
- Не добавляй несуществующие ссылки и фиктивные результаты.

### 5. Проверить

- Запусти тесты/линтер/сборку, подходящие текущему стеку.
- Для UI проверь пустое состояние, нормальный результат, ошибку и адаптивность, если это относится к задаче.
- Для retrieval проверь несколько известных запросов и происхождение документов.
- Для LLM/RAG проверь, что ответ зависит от предоставленного контекста, а при недостатке контекста нет уверенной выдумки.
- Если команда проверки недоступна — прямо укажи это и выполни доступную ручную проверку.

### 6. Обновить документы

Обновляй документы, если изменились интерфейс, контракт, источник данных, способ запуска, переменные окружения, требования, ограничения или архитектура. Не создавай дублирующую документацию без причины.

### 7. Отчитаться

Используй формат из корневого `AGENTS.md`: сделано, требования, проверки, ограничения и ближайший шаг.

## Когда обязательно пересмотреть спецификацию

- изменяется основной пользовательский сценарий;
- появляется новый экран или существенное состояние UI;
- меняется формат API, структуры документа или источник истины;
- меняется метод retrieval/ранжирования или способ генерации ответа;
- вводятся внешние сервисы, ключи, хранение данных либо существенные зависимости;
- появляются новые заявления о безопасности, токсичности или медицинском применении растений.
